## 2. 技术栈选型

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 前端框架 | Vue 3 + Vite | 轻量、上手快、生态成熟 |
| CSS 框架 | Tailwind CSS | 快速构建精美 UI，无需写大量自定义 CSS |
| Markdown 渲染 | marked + @tailwindcss/typography | marked 转 HTML + prose 类精美排版 |
| 思维导图 | markmap-lib + markmap-view | 开源成熟，支持 Markdown 输入，交互性好 |
| 后端框架 | FastAPI (0.135+) | 异步高性能、原生 SSE 支持、Python 生态 |
| 核心能力 | yt-dlp | 14w+ Star，支持 1800+ 网站，社区活跃 |
| AI 大模型 | DeepSeek (deepseek-chat) | 兼容 OpenAI 协议，通过 openai SDK 调用 |
| 数据库 | 无 | 轻量设计，无需持久化存储 |

### 3.2 下载视频（服务端代理模式）

```
POST /api/download
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "format_id": "137+140"
}

Response: 视频文件流 (Content-Type: video/mp4)
Headers:
  Content-Disposition: attachment; filename="视频标题.mp4"
```

> 注：前端实际下载已改用 3.4 的 SSE 流式接口（带实时进度），本同步接口保留作兼容与调试用途。

### 3.3 获取直链

```
POST /api/direct-url
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "format_id": "137"
}

Response (200):
{
    "success": true,
    "data": {
        "direct_url": "https://rr3---sn-xxx.googlevideo.com/...",
        "ext": "mp4",
        "filesize": 52428800
    }

```

### 3.4 服务端下载（SSE 实时进度）

```
POST /api/download/stream
Content-Type: application/json

Request:
{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "format_id": "137+140",
    "audio_only": false
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - progress → {status, percent, downloaded, total, speed, eta, error}
      status: starting / downloading / processing / finished / error
      percent: 0~100，总大小未知时为 null（前端展示不定进度动画）
      processing 表示合并音视频 / 转码阶段（无字节进度）
  - done     → {download_id, file_url, filename}
  - error    → {message}

GET /api/download/file/{download_id}
Response: 视频文件流 (Content-Disposition: attachment)
说明: 服务端下载完成后，前端通过该接口把临时文件交给浏览器保存
```

进度状态机、采集算法与临时文件清理的设计细节见第 5 节「下载进度模块设计」。

### 3.5 AI 视频总结（SSE 流式）

```
POST /api/summarize
Content-Type: application/json

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "language": "zh"
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - subtitle  → 字幕数据（含 segments 时间戳列表和 full_text）
  - summary   → 总结摘要（流式 token，逐字输出）
  - mindmap   → 思维导图 Markdown（一次性返回）
  - done      → 完成信号
  - error     → 错误信息
```

### 3.6 AI 视频问答（SSE 流式）

```
POST /api/chat
Content-Type: application/json

Request:
{
    "url": "https://www.bilibili.com/video/BV1mAAmzqEfP",
    "question": "这个视频用了什么技术栈？",
    "subtitle_text": ""
}

Response: SSE 事件流 (Content-Type: text/event-stream)
事件类型：
  - answer    → AI 回答（流式 token）
  - done      → 完成信号
  - error     → 错误信息
```

## 4. 下载模式策略

当前版本统一走**服务端代理下载**（`POST /api/download/stream`，SSE 实时进度）：服务端通过 yt-dlp / 抖音专用模块完成下载，完成后由前端经 `GET /api/download/file/{id}` 取回文件。该模式兼容有防盗链的平台，不受浏览器跨域与直链时效限制，且下载全过程对用户可见。

`/api/direct-url`（解析视频直链）保留：适用于后续「浏览器直下、不占服务器带宽」的模式扩展（见第 9 节）。

## 5. 下载进度模块设计

服务端代理下载耗时较长（服务端先从平台下载，再转交浏览器），为避免用户面对无反馈的等待，下载全过程通过 SSE 实时推送进度。技术选型与 AI 总结一致（SSE），不引入 WebSocket。

### 5.1 进度状态机

```
starting（准备中）
   → downloading（下载中，有字节进度：percent / downloaded / total / speed / eta）
      → processing（处理中：合并音视频 / MP3 转码，无字节进度）
         → finished（完成）
任意状态 → error（失败，携带 message）
```

### 5.2 进度采集与计算（DownloadProgress，downloader.py）

- **线程安全状态对象**：下载工作线程写入（yt-dlp 钩子 / 抖音回调），SSE 生成器每 0.3s 读取快照 `snapshot()`，与上次快照不同才推送事件
- **yt-dlp**：`progress_hooks` + `postprocessor_hooks` 上报
  - 合并模式（如 `137+140`）分两段下载：视频流 → 音频流 → ffmpeg 合并；已完成分段的字节数累加进 `parts_done`，百分比 = `(parts_done + 当前分段已下载) / (parts_done + 当前分段总大小)`
  - HLS/DASH 分片流按 `fragment_index / fragment_count` 估算分段进度
  - 后处理器（合并 / MP3 转码）启动时进入 `processing`
- **抖音**：`requests` 流式写入时按 0.2s 节流回调（按 `Content-Length` 计算总量与速度）；ffmpeg 抽音轨前回调 `processing`（抖音音频是"先下整视频、再抽音轨"，故进度条先走一遍视频大小的下载）
- **兜底规则**：处理完成前百分比封顶 99.9%（防止"假完成"）；总大小未知时 `percent=null`，前端展示不定进度动画

### 5.3 前端展示（VideoResult.vue + App.vue）

- 下载按钮下方进度条：状态文案 + 百分比 + 已下载/总大小 + 速度 + 剩余时间（`tabular-nums` 对齐）
- 总大小未知 / 准备阶段：不定进度滑动动画；处理中：进度条呼吸闪烁 + 「正在处理（合并音视频 / 转码）…」
- 完成态：进度条变绿（success）显示「下载完成」；收到 `done` 事件后通过隐藏 `<a>` 访问 `file_url` 触发浏览器保存（同源 GET，`Content-Disposition: attachment` 自动命名）
- 下载中：按钮禁用并显示「下载中 NN%」；SSE 解析复用 `api/sse.js` 的 `consumeSSE`（与 AI 总结共用）
- 解析新视频时重置进度状态；完成后保留「下载完成」展示

### 5.4 文件取回与临时文件清理（main.py）

- `done` 事件携带 `{download_id, file_url, filename}`；`GET /api/download/file/{download_id}` 校验任务存在且文件在盘后以 `FileResponse` 返回
- 每次发起新下载时清理下载目录中超过 1 小时的临时文件；下载任务状态记录 1 小时后从内存移除；状态表超过 500 条整体清空防膨胀
- 旧同步接口 `POST /api/download` 保留兼容，前端已不再使用

### 5.5 异常与边界

- **下载失败**：`error` 事件携带 message（已剥离 yt-dlp 的 ANSI 终端色码），前端 alert 提示
- **用户中途关闭页面**：SSE 连接断开，后台下载线程继续完成，文件由 1 小时清理兜底，不影响服务
- **同一时间单任务**：下载期间按钮禁用，避免并发下载互相干扰

## 8. AI 视频总结模块设计

### 8.1 字幕提取策略

```
用户输入 URL
    ├─ B站视频？ → B站专用 API（x/v2/dm/view）获取 CC 字幕 / AI 字幕
    │              ├─ 成功 → 返回字幕
    │              └─ 失败 → 回退到 yt-dlp
    └─ 其他平台 → yt-dlp 提取字幕
                   ├─ 人工字幕（优先：zh > en > ja > ko > 其他）
                   ├─ 自动字幕（同上优先级）
                   └─ 无字幕 → 返回提示
```

字幕格式：VTT → 解析为结构化分段 `[{start, end, text}, ...]`

### 8.2 AI 调用流程

1. 提取字幕文本（截断至 15000 字符）
2. 调用 DeepSeek API（stream=True）流式生成总结摘要
3. 调用 DeepSeek API 生成思维导图 Markdown
4. 通过 SSE 实时推送给前端

### 8.3 SSE 数据传输

- **summary / answer 事件**：token 通过 `json.dumps()` 编码后发送，避免换行符被 SSE 协议拆行导致前端丢失格式
- **前端解析**：严格按照 SSE 规范处理，`data:` 行用 `\n` 拼接，空行触发事件派发，`summary` / `answer` 数据先 `JSON.parse` 解码

### 8.4 前端渲染

- **总结摘要**：marked 解析 Markdown → `@tailwindcss/typography` prose 类排版 + 自定义样式覆盖（h1/h2/h3/blockquote/code/pre/table/a 等），流式打字机效果
- **字幕文本**：带时间戳的列表，支持展开/收起，支持下载字幕文件（SRT / VTT / TXT 三种格式）
- **思维导图**：markmap-lib 转换 Markdown → markmap-view 渲染 SVG，支持全屏展示（Fullscreen API），支持下载高清 PNG（4K+）和 SVG 矢量图
- **AI 问答**：对话式 UI，流式输出 + 光标闪烁动画，AI 回复使用 prose 排版

### 8.5 思维导图导出策略

- **PNG 导出**：通过 `<g>` 根节点的 `getBBox()` 获取完整内容边界（不受用户缩放/平移影响）→ 将 `foreignObject` 替换为 SVG `<text>` 元素（规避 Canvas tainted 安全限制）→ 设置完整 `viewBox` + 4x 以上缩放 → Canvas 绘制 → `toBlob()` 导出
- **SVG 导出**：克隆 SVG DOM → 通过 `getBBox()` 重设完整 `viewBox` → 内联 markmap CSS → 序列化为独立 SVG 文件
- **全屏展示**：使用浏览器原生 Fullscreen API，全屏后调用 `markmapInstance.fit()` 自适应
